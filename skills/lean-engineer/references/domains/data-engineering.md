# 数据工程检查

适用于 ETL、数仓、批流处理、业务指标、特征管道和历史重算。按数据用途和错误传播范围判断后果；普通分析与结算、财务或监管报告不自动同档。沿用 [风险分档](../risk-gates.md) 与 [验证与证据](../verification.md)，命中事务或消息问题时合并对应后端检查。

## 先固定数据契约

仅对本次受影响的数据及其下游列出输入与输出、行粒度、业务主键、去重键、字段与空值语义、单位/币种/精度、时区、时间窗口、源快照或分区，以及下游消费者。指标写明统计人群、分子分母、排除条件和版本；流式任务再区分事件时间、处理时间、watermark、窗口与迟到处理。业务口径不明时先取得依据，不能靠现有 SQL 反推正确答案。

## 命中后执行

| 触及内容 | 检查与反例 | 通过条件 |
| --- | --- | --- |
| JOIN、过滤、聚合或维表 | 构造重复键、缺失匹配、空值、边界日期和适用的历史维度变化；核对连接前后的行数、唯一键、匹配率及分组金额 | JOIN 基数符合预期，没有静默丢行或多对多放大；按契约对账。不能只比总行数或总金额，分区、租户或维度间的错误可能互相抵消 |
| 增量、重试与检查点 | 固定输入与代码版本重复运行；在部分写入、提交前后和检查点更新处失败再恢复；检查去重状态的保留期限 | 按承诺的交付语义不重记、不漏记；失败结果不冒充完整数据。引擎声称 exactly-once 不能替代外部 sink 和副作用的端到端检查 |
| 流式时间与迟到数据 | 注入乱序、重复、窗口边界及超过允许迟到范围的事件；检查状态清理与重新计算 | 窗口归属与项目时间语义一致；迟到数据有明确的丢弃、旁路、修正或重算策略及可观测记录。watermark 是进度估计，不证明再无迟到事件 |
| schema 或指标口径变化 | 用旧/新 schema、真实匿名样本及独立算例对照；列出下游报表、接口、特征消费者与切换窗口 | 兼容或迁移方式明确；合法业务变化与意外差异分开。旧结果有错时不能要求逐字一致，也不能用新实现生成的期望值自证正确 |
| 回填、重算与输出发布 | 先在受控分区或影子输出演练；固定输入版本、范围、代码、并发、预计扫描量和停止条件；检查部分完成与下游重复消费 | 不静默覆盖范围外数据；按存储实际能力完成原子发布或显式完成标记及消费约束。验证恢复旧输出或重新生成的路径；回滚代码不等于撤回已消费数据 |
| 特征与训练数据 | 按样本事件时点重建可用特征，检查历史维表和晚到更新，比较离线与在线转换 | 不使用预测时刻不可获得的信息；时间切分与特征可用性符合项目约定，避免未来信息泄漏 |
| 数据量或分布改变 | 在代表性规模下查看执行计划、扫描分区、shuffle、倾斜、内存与处理时延 | 资源和新鲜度满足项目预算；小样本正确不证明全量可运行。优化后仍通过数据对账 |

## 质量断言与证据

1. 按受影响的数据契约选择非空、唯一性、引用完整性、值域、时效、覆盖分区和业务对账断言；记录阈值来源。异常数据允许存在时，按合同隔离、计数与报告，不能静默丢弃来让任务成功。
2. 保留可手算或独立实现核对的小样例，另在受控历史快照上比较。记录输入版本、运行 ID、查询/作业版本、窗口、行数、差异分布及原始报告位置。抽样结果只证明样本范围；“任务成功退出”不证明数据语义正确。
3. 发布前验证失败是否阻断不合格输出，或按已有合同将其标为不完整、隔离并通知下游。检查数据新鲜度与质量异常的可观察入口，不将仅有作业存活监控写成数据质量监控。
4. 生产回填、覆盖和昂贵全量重算遵循任务已有授权与预算。没有必要输入或环境时，将对应项记为 `blocked`，仍完成可运行的小样例检查；不得自行扩大到全库或替用户接受错误数据。
