# 安全差异审查

## 职责与触发

本专题补充安全变化的历史对照、影响传播和候选核验。风险等级仍由 [风险分档](risk-gates.md) 决定，独立性与发现处置仍由 [独立审查协议](review-protocol.md) 决定，证据和交付状态仍由 [验证与证据](verification.md) 决定。读取本专题不自动升级档位，也不增加通用质量门。

出现以下任一信号时使用：

- 新增、移除、移动或改变身份、授权、租户、输入校验、输出处理、秘密保护或可信边界。
- 修改共享函数、入口、消息任务或配置，可能改变上述保护的实际执行路径。
- 用户要求核对安全修复是否回归，或追踪安全变更的影响范围。

只改文案、注释、等价格式或无安全含义的内部计算，不因文件名、仓库大小或引用数量触发。能否影响安全边界尚不清楚时，先围绕变更点取证，再决定是否进入本专题；不得把尚未查明当作无影响。

## 先确定保护了什么

记录原始与当前基线、变更对象及应保持的不变量。对删除或移动的保护，说明原来限制了谁、什么输入或状态，以及新路径由哪里承担该责任。保护移除是检查信号，不直接等于漏洞；旧实现也可能错误或已被替代。

已有历史时，定向核对相关提交、问题记录和回归测试，区分修复依据、设计意图与当前实际行为。提交标题或注释不能独立证明缺陷存在或修复有效。重命名、移动及生成代码需要先确认对应关系和源定义。

历史取证以读取快照和差异为限，不切换、重置或覆盖正在工作的目录，也不因读取历史而获得执行权限。确需旧版行为对照时，先核对副作用和已有授权，再按实现与验证协议由有执行权限的一方在隔离副本或夹具中运行。只读审查者仍只提出场景并核对结果，不直接执行。

没有 Git 时使用原始文件、哈希、合同或其他可核对材料。确实缺失的历史记录为 `unknown`：仍可审查当前源码，但不得编造旧版行为或将来源不明的问题认定为本次引入。缺少材料妨碍必需判断时，相关检查为 `blocked`；历史证据不完整不抹去已经成立的当前源码发现。

## 沿同一安全不变量追踪

从变更点向上确认谁能够进入，向下确认会读取、返回、修改或发送什么。核对实际调用与分发关系，包括命中的包装层、路由注册、回调、消息消费者和后台入口。搜索与调用图只用于发现候选，必须阅读关键边的实现。

对每条相关入口分别检查：身份和租户从何处获得，调用方能控制哪些值，保护在何时、哪一层生效。若变化涉及异步、重试或状态切换，再核对保护是否在执行敏感操作时仍成立。一个 HTTP 入口的校验不能替代对后台任务或其他入口的核对。

`quick` 的直接范围不足以判断本次安全变化时，沿该不变量扩展必要的传递路径；其他范围保持用户约定，不自动变为全仓审查。停止追踪须说明理由并关联当前基线的证据：已查到相关副作用，或已确认变化不会继续传播，或已确认可信保护覆盖这条实际路径。不能仅因达到固定层数、搜索无结果或看到一个校验函数就停止。

动态调用、外部消费者或不可读配置无法查明时，列明未知边和结论影响。已检查路径的结论不得外推到未知路径。调用数量可以描述观察到的范围，不能单独决定严重度、可利用性或覆盖完整性。

## 对候选问题同时寻找支持与反证

围绕实际候选补齐以下因果链，不要求为不存在的问题填写漏洞模板：

1. 可能触发问题的主体及其已有权限、可控制的输入、必要状态或时序。特定身份、输入或状态是合法的缺陷条件，不因其有条件而直接过滤。
2. 可到达的真实入口，以及如何经过本次变化到达敏感结果。标明每个关键假设的来源；不能仅凭危险函数、公开签名或工具告警认定可利用。
3. 当前防护是否确实覆盖这条路径：可信身份、对象约束、安全绑定、部署策略或其他阻断条件。主动寻找能推翻候选的证据，不能只确认自己的第一种解释。
4. 违反了哪条要求、可能造成什么后果，以及哪些后果仍待验证。严重度按实际资产、权限和后果判断；不得编造损失金额、受害数量或生产事故。

源码可支持其范围内的缺陷判断，但不替代运行和部署证据。防护已被当前证据证明有效时，说明候选为何不成立；防护位置、配置或触发条件未知时，保留待验证项，不把“尚未证明可利用”写成“已证明安全”。

需要验证时，提出最小的合法路径与拒绝路径检查及独立预期。只在已授权的隔离环境使用无害夹具，由有执行权限的一方运行。不得为复现问题读取真实秘密、探测外部目标或在生产制造越权、资金、删除等副作用。缺少必要环境时保留对应验证缺口。

## 接回现有记录与完成判定

复用既有检查对象、发现 ID、置信度、来源分类和处置状态。把历史依据、路径范围、保护与反证、剩余假设记录在现有证据或补充审查记录中；不创建第二套漏洞等级或台账 schema。

后端记录按原六专题关联检查和证据；其他领域按验证协议补充记录，并汇总所有必需检查。必需项失败、阻塞或未执行仍影响整体状态，不能只凭台账结构通过宣称完成。允许零发现，但必须交代已查范围和未知项；修复后复验原问题与合法业务，继续遵守原复审轮次和历史要求。
