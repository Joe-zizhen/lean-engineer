# 嵌入式检查

适用于固件、驱动、RTOS、传感器、执行器和设备升级。普通设备不自动等同于硬实时或安全关键系统。先确认实际硬件与失效后果，再按 [风险分档](../risk-gates.md) 定档；证据沿用 [验证与证据](../verification.md)。

## 先确定约束

记录 MCU/板卡版本、外设与连接、工具链及优化参数、RTOS/SDK、固件构建和部署方式。对本次影响的路径列出 RAM/Flash/栈、周期与截止时间、供电条件、安全状态及恢复入口，并指向规格或项目依据。未定义的实时性或资源预算不得由 agent 随意编造。

## 命中后执行

| 触及内容 | 检查与反例 | 通过条件 |
| --- | --- | --- |
| 中断与任务交互 | 标出 ISR、任务和 DMA 的读写所有权；沿调用链检查 API 的上下文及中断优先级限制、临界区、锁顺序、队列满和抢占 | 不在禁止阻塞的上下文等待；共享数据在所需内存顺序下保持一致。不能把 `volatile` 当作原子性或互斥保证；FreeRTOS 等平台须核对对应 ISR API 与端口限制 |
| 内存与缓冲区 | 检查 map/size、任务栈与中断栈、长度及单位换算；注入边界长度、分配失败、队列溢出和适用的最大嵌套负载 | 不越界、不静默截断关键数据；拒绝、丢弃或降级按契约发生。栈水位是已执行负载的观测，不是所有路径安全的证明 |
| 实时性与看门狗 | 在目标负载下记录最坏已观测延迟与抖动，含中断竞争、长临界区和外设等待；验证超时与任务停滞 | 满足已规定的截止时间及故障响应。平均值不证明硬实时；硬截止时间还需项目要求的最坏情况分析。不能靠延长超时或无条件喂狗掩盖失效 |
| 外设、传感器与控制输出 | 核对寄存器、单位、字节序、量程、校准与 SDK 契约；检查断连、无效值、超量程、陈旧采样及计数器回绕 | 输入无效时按设计保持、降级或进入安全状态；复位和异常路径不能产生危险输出。按硬件规格选取适用边界 |
| Flash/EEPROM 与供电中断 | 在隔离台架或受控仿真中断写入各关键阶段，检查启动恢复、记录完整性及擦写策略 | 恢复到有效状态或可诊断故障，不把半写数据当成有效配置；写入频率与寿命依据匹配 |
| 固件更新、启动与回退 | 检查镜像真实性和完整性、板型/版本匹配、分区与引导配置；在下载、切换、首次启动阶段注入失败 | 依据实际能力验证恢复、回退或现场维修路径；检查新旧固件的数据兼容，以及安全反降级策略对回退的限制。不能假设所有分区都支持 A/B 回滚，也不能假设 OTA 失败必然变砖 |

故障注入先明确台架隔离、输出限制、恢复步骤和停止条件。只在任务已授权的设备与范围内执行；不对生产设备或真实执行器擅自做破坏性试验。缺少安全试验条件时继续可行的源码/仿真检查，设备项记为 `blocked`。

## 最小证据与限制

- 主机单测适合算法与协议逻辑；仿真或模型只覆盖其假设。硬件时序、电气交互和功耗结论需要适合的真机证据。
- 波形、逻辑分析仪、trace 或设备日志按待证明事项选择，不要求每次都用示波器。记录固件与板卡、测试输入、探测点、采样条件、负载、预期上限和原始产物位置；检查测量插桩是否改变时序。
- 失效涉及人身安全、设备损坏或不可恢复后果时，执行风险分档中的独立审查。项目要求功能安全或其他认证时，依据实际标准版本、适用范围和安全等级补齐专门流程。本 skill 的检查通过不能冒充认证完成。
