# 可复用能力库

## 用途与位置

能力库保存业务代码可以导入调用的实现。能力索引帮助后续任务找到实现和调用方法。索引不替代源码。

默认位置为项目根目录的 `powers.md` 和项目内的 `mymodule/`。模块代码必须位于语言或构建系统识别的源码路径中。例如，Java 文件需要有效的 package 和源码目录，Python 模块需要可导入路径。不要通过临时修改全局搜索路径来掩盖接入问题。

项目已有等价索引或共享源码模块时，沿用其位置与放置规则，并向用户说明映射。不要另建一套目录或索引。已有位置不能从项目规则和源码确认时，先定位或澄清。默认路径只用于没有既有约定的项目。

Skill 规定流程。业务模块及其索引属于业务项目，不写入 skill 安装目录。不自动创建跨项目全局库、包注册服务或发布流程。

## 实现前查找和调用

1. 先读能力索引。按目标能力、别名、输入输出和使用条件查找候选。
2. 命中后打开源码，核对公开入口、依赖、平台、失败行为及本次需求。索引中的名称或验证记录不等于本次可用。
3. 满足需求时直接导入并调用。不要复制实现，也不要增加没有用途的包装层。运行实际调用方的导入或构建检查，并验证本次使用的行为。
4. 没有索引或索引未命中时，定向检索项目现有源码。已有适用实现时复用，并在本次授权的实现任务中补登记。不要把未登记当作未实现。
5. 候选不适用时，说明具体差异。先判断能否兼容扩展已有能力。需要改变现有调用契约时，按风险分档验证旧调用方。不要仅因名字不同就新建重复能力。

## 首次实现与收录

本次功能确实需要实现，且其输入、输出、依赖和副作用能形成独立边界时，将可复用部分收录到能力库。第一个真实调用方即可触发收录，不要求已有第二个调用方。仅有未来设想时，不提前实现。

默认一个能力一个命名清楚的代码文件。文件名与公开入口遵循项目和语言规范。复杂能力需要多个文件时，使用一个职责明确的小目录。不要为追求单文件而混合职责。

把调用方提供的数据和必要资源作为参数或项目已有的依赖传入方式。不要反向依赖某个业务页面、页面私有状态或固定测试账号。不要为了泛化而创建尚无用途的接口、插件系统或配置层。

模块默认不在导入时启动后台任务、发起网络请求、写入持久化数据或修改全局配置。这些副作用由调用方通过明确入口触发。模块持有任务或资源时，按实际需要提供停止、取消或释放入口。框架明确要求的加载期注册行为按项目约定处理，并写明该行为。

只封装本次已需要的能力。业务编排留在调用方。例如，闹钟模块负责约定的创建和取消，具体页面的表单状态不进入模块。平台权限或运行条件必须写明，不能声称文件放入目录就已经可运行。

在首次收录真实实现时创建默认目录和索引。没有可收录对象时不创建空库。模块实现、调用方接入、对应验证和索引更新属于同一次改动。

## 索引内容与维护

每项记录以下调用必需信息。短信息用一行表格，复杂调用链接到源码旁的示例，不复制整份 API 文档。

| 能力与检索词 | 项目相对代码路径 | 公开入口与最小调用 | 使用条件与边界 | 验证依据 |
| --- | --- | --- | --- | --- |

路径必须指向实际源码。调用示例必须与当前签名一致。使用条件只记录实际存在的平台、依赖、权限、生命周期或副作用限制。验证依据记录可重跑入口及最近一次结果，未验证项明确记录 `not_run` 或 `blocked`，不得列为可直接使用。

修改已收录能力的路径、接口或使用条件时，同步索引并验证受影响的真实调用方。删除或迁移仍须遵守项目授权，不能以索引维护为由清理无关代码。索引与源码不一致时，以当前代码和契约取证，并在授权范围内修正索引。

只读审查只报告候选、重复实现或索引失配，不创建目录、搬移源码或修改索引。
