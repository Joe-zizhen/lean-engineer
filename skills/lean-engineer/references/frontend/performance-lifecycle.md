# 性能与生命周期

## 检查对象

列出生产构建资源、关键请求、渲染路径、订阅、计时器、 observer、事件监听、缓存和大集合。记录组件挂载、更新和卸载生命周期。

## 必须成立的不变量

- 页面离开或组件卸载后，不再接收无效事件或写入错误页面。
- 网络、内存、渲染和主线程工作具有与任务匹配的上限。
- 优化结论来自生产模式和目标设备测量，不来自函数行数或主观判断。
- 缓存、防抖、虚拟化和预加载只解决已测量的瓶颈，不改变数据正确性。

## 必造反例

- 快速切换页面、实体和筛选条件，观察迟到事件和重复订阅。
- 大列表、长文本、慢网络、低性能设备和后台标签页。
- 组件反复挂载与卸载，检查计时器、连接和内存是否增长。
- 第三方资源失败、阻塞或返回过期内容。

## 最小证据与复验

- 使用生产构建。记录设备、浏览器、网络、数据量、样本条件和测量方法。区分实验室测量与真实用户数据。
- 按核心旅程测量适用的 LCP、INP、CLS、长任务、关键请求和资源变化。Lighthouse 总分不能代替具体指标和瓶颈证据。
- 通过重复挂载与卸载检查事件监听器、计时器、observer、订阅和内存趋势。单个内存快照不能证明泄漏。
- 按风险选择页面、数据量、网络和设备组合，记录测量分母和未测原因。优化前后必须复验功能，并在相同条件下比较数值。没有测量时，不声称更快、更省或已经解决性能问题。

## 定位与优化步骤

用于性能任务，或改动确实触及下表风险时。普通局部改动只复验受影响项，不自动启动全站性能工程。

1. 固定核心旅程、生产构建、设备、网络、数据规模及冷暖缓存条件。先复用项目预算，记录指标、统计口径和阈值来源。没有预算仍可定位与对比；需要判定“达标”时先明确验收目标，不能把工具默认值或单次最快值充当项目门槛。
2. 留下基线与原始 trace、请求瀑布或 profiler 输出。重复测量并记录次数、分布和异常条件；真实用户数据按设备与页面分组，说明时间窗口、样本和分位数。实验室中一次交互耗时不能冒充线上 INP 分位数，TBT 也不是 INP。
3. 从现象定位到耗时阶段和具体资源或调用栈，再选择一项有证据支持的改动。框架专属问题使用当前版本的官方 profiler 或文档，不默认添加 memo、缓存或手写调度。
4. 同条件复测并检查功能、可访问性和资源代价。波动覆盖了改进幅度时保留“不确定”；改善某个指标不等于满足全部预算。

| 现象 | 如何定位 | 根据证据选择措施并检查副作用 |
| --- | --- | --- |
| 首屏或 LCP 慢 | 确定实际 LCP 元素；分解 TTFB、资源发现延迟、下载时长和渲染延迟，结合网络瀑布及主线程 trace | 分别处理服务响应、资源可发现性、图片大小或阻塞渲染。关键首屏资源不要盲目懒加载；`preload`、`preconnect` 只用于已确认的关键资源，`prefetch` 不替代当前页面关键资源优先级。 |
| JS 下载或执行重 | 查看生产包组成、重复依赖、实际使用范围、解析执行和懒加载请求链 | 按旅程边界拆包，检查拆分是否产生串行瀑布；tree-shaking 未生效时核对模块格式与副作用声明，不为减包误删必要初始化。 |
| 点击或输入卡顿 | 定位具体交互的输入等待、事件处理、下一帧呈现三段；查看长任务与组件提交耗时 | 再决定减少计算、拆任务、缩小更新范围或虚拟化；使用 memo 前后对比收益，检查陈旧值、焦点和键盘路径。 |
| 布局跳动、字体或图片拖慢 | 查看 layout shift 的时间与关联元素，确认根因资源；检查实际选中的图片、显示尺寸、字体下载和替代字体 | 预留图片或异步区域尺寸，校准 `srcset`/`sizes` 和格式回退，权衡字体显示策略；关联到的偏移元素不一定是制造偏移的元素。 |
| 滚动或动画掉帧 | 在 trace 中区分脚本、layout、paint、composite，查强制同步布局 | 可行时选 `transform`/`opacity`，但仍实测；不保证用了这两个属性就无主线程瓶颈，不滥用 `will-change` 增加图层内存。 |
| 页面反复进出后变慢 | 固定进入、操作、离开序列，比较多轮稳定后的堆、DOM、监听器与连接；用快照的保留引用链找到未释放对象 | 定位捕获旧组件的闭包、全局监听、timer、observer、订阅或连接的所有者；释放或转交由该所有者负责，不能把仍供其他调用方使用的共享连接直接关闭。 |
| 弱网、缓存或离线异常 | 在确有缓存或离线能力时，检查请求头、缓存命中、重新验证、版本更新与断网重试 | 核对用户隔离、过期语义及失败提示；使用 Service Worker 时验证升级和旧缓存清理。没有离线需求时，不为一次性能优化新增离线架构。 |

## 通过条件

适用预算满足、关键行为复验通过，且未出现被掩盖的回归，才可写“达到本次目标”。只有对比改善时写清改善幅度与条件。没有预算时不宣称满足生产容量或所有用户体验；缺失的设备、旅程或真实用户证据单列。
