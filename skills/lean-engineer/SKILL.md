# lean-engineer

用满足需求的最小改动交付可验证结果。先查能力索引并理解真实调用链。已有能力直接调用。新实现中边界明确的可复用能力收录到项目能力库，供后续任务调用。

## 职责与优先级

本文件只拥有任务分流、方案选择顺序、风险流程和交付状态。详细实现纪律、领域 Review、独立审查和专项验证各有唯一权威。

系统、宿主、用户和项目指令按既有优先级执行。本 skill 不把安装视为对任意写入的授权。用户本轮明确关闭本 skill 时，本文件不执行。

纯产品需求交给需求流程。性能或容量的测量型诊断属于本 skill 的 Review 范围，按命中的领域专题执行。测量型诊断必须包含工作负载和可执行的测量入口。

其他根因未定的故障不由本 skill 主导，使用项目或宿主已有的调试流程。没有该流程时，先读取错误、固定复现、在组件边界取证，再以单假设最小验证形成足以选择修复边界的因果说明，然后决定是否进入实现。开放性方案设计使用用户选择的设计流程。项目已有强制编码 skill 时，不重复生成第二套证据。合并相同检查，保留更严格要求。

## 工作卡

1. 确定用户要的是实现、只读审查、验收还是工具搭建。只读审查不修改实现。
2. 编码、改动或验收前完成下方 [基础读取](#基础读取)，按实际后果和调用方证据定档。
3. 继续判断 [条件追加](#条件追加) 和领域路由。所有命中项累计处理，不能选中一项就结束。未读取的文件不得写成已执行。
4. 按方案阶梯选择最小实现。实现功能或修改可复用能力时，执行能力库的查找、调用、收录和索引同步。用户明确要求的能力不得静默削减。
5. 运行与改动和风险匹配的检查。交付时区分通过、失败、阻塞和未运行。

## 按需路由

Web 前后端、原生移动端、嵌入式和数据工程检查都是本 skill 的内置专题。只读取本次任务命中的文件；同一系统跨多个领域时，组合必要检查并合并重复证据。

### 基础读取

按本轮实际动作判断，“编码”和“实现”不是互斥任务名。

- **代码实施**：准备新增、修改、修复、重构、删除代码，或进行复用接入、依赖接入等实现工作时，首次实施前同时读取 [风险分档](references/risk-gates.md) 和 [实现纪律](references/implementation.md)。源码中的文案修改也适用。小改、受控大改和厚审都遵守实现纪律，风险档位不替代实施约束。
- **其他适用改动或验收**：仍读取 [风险分档](references/risk-gates.md)，再按下表读取适用的验证、审查和领域规则；仅验收不自动进入代码实施。
- **只读阶段**：纯只读 Review 不加载实现纪律，也不修改实现；同时承担验收时仍执行验收读取要求。经授权转入代码实施时，在首次实施前补齐上述基础读取，不能继续沿用只读豁免。

## 方案阶梯与实现纪律

按顺序选择第一个能够满足真实需求的方案：

1. 不需要实现时，不写。
2. 项目已有能力目录和源码可复用时，复用。索引只用于发现，源码才是事实。
3. 标准库或原生平台可以完成时，优先使用。
4. 已安装依赖可以完成时，按实际版本和项目用法使用。
5. 成熟专项库明显更省时，先评估维护、兼容、许可证、传递依赖和移除成本。新增依赖必须服从项目授权。
6. 否则写最小实现。单用途代码不造通用抽象。

默认使用项目根目录的 `powers.md` 作为能力索引，使用项目内 `mymodule/` 存放可导入代码。已有等价索引、源码模块或语言布局约定时沿用，并说明实际位置，不另建平行库。具体收录与调用规则见 [能力库](references/reusable-capabilities.md)。

详细的方案操作约束、实现纪律和编码不变量由 [实现纪律](references/implementation.md) 拥有；动作范围和读取时机统一按 [基础读取](#基础读取) 执行，不用风险表中的摘要替代完整实施约束。

## 交付约束

- 检查必须真实运行。搜索命中只证明搜索范围内的存在或不存在。
- 不得用跳过测试、删除有效测试、放宽阈值或 mock 被测对象来制造通过。需求变化导致测试更新时，必须保留新的独立依据。
- 用户或项目可以要求超过当前档位的验证。执行额外验证不是错误。
- 声称完成前，逐条对照用户要求。每项给出实际证据或明确缺口。
- 只有全部必需检查均为 `passed` 或有依据的 `not_applicable` 时才使用 `verified`。存在未运行或阻塞项时使用 `partial`。存在失败项时使用 `failed`。
- 质量门通过不等于需求正确。发布、风险接受和业务语义由授权人员决定。
