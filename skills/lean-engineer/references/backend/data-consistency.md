# 数据一致性

## 检查对象

列出读写路径、表或集合、字段含义、事务、锁、唯一约束、缓存、迁移、回填、备份和恢复。写路径变化必须检查全部读路径。

## 必须成立的不变量

- 业务唯一性和关键状态约束由可信数据层保证。应用层检查不能单独替代必要的数据库约束。
- 多步写入要么达到定义的原子结果，要么存在可恢复的补偿与状态查询。
- 事务隔离、锁顺序和版本检查与真实并发语义一致。
- 外部调用不使数据库事务长期处于不可控状态。
- 新旧代码在兼容窗口内能够读取和写入同一数据。
- 代码回滚与数据恢复分别定义。不可逆操作必须有明确授权和恢复依据。

## 必造反例

- 两个请求同时创建或更新同一业务对象。
- 在事务中途、回填中途或外部调用后发生故障。
- 重复执行迁移、回填、补偿和恢复。
- 旧代码读取新字段，新代码读取旧数据。
- 读副本延迟、锁超时、死锁和唯一约束冲突。

## 迁移与恢复证据

破坏性重命名或删除需要明确的扩展、迁移、收缩步骤。回填需要批次、上限、检查点和重复执行语义。索引和 schema 变更需要评估锁与运行影响。

在隔离的真实数据库上演练迁移、旧新代码组合和恢复。没有实际恢复演练时，不得写“备份可恢复”。

查询次数、索引和缓存建议必须有负载或测量依据。深入性能审查按 [交付与运行](delivery-operations.md) 的内置流程执行，不得编造延迟或命中率。

## 复验

验证合法写入、冲突写入、故障点恢复、重复执行和旧调用方。检查日志、行锁、约束或任务状态只能证明各自范围，不能单独证明整个业务结果。
